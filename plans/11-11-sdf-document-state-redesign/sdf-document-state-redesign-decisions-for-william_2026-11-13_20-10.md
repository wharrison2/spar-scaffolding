# SDF document state redesign: decisions for William

Every open decision on the redesign, its cleanup and the design improvements, in one list. Numbers 1 to 13 keep the numbering used in the cut list and the cleanup plan. "Blocks" names the work that waits on it.

## Principle (2026-11-13)

The stage files are the source of truth. The event log (`document_events.jsonl`) is written, never read by pipeline code; only tests read it, to check what was written. Two places read it today and change: the loader's dealt value ids (`document_state_loader.py:326`, decision 6) and `run_corpus_step`'s check for unchanged outcomes (`step_runner.py:242`), which now appends an event per document every time a corpus step runs (consideration assignment, score gate, near-duplicate cull), repeats included. Chosen over comparing against the stage files before appending: nothing consumes the log, so the repeated lines (about 1,000 short lines per resume into layer 4 on a 500-document run) cost nothing, and each pass is already grouped by the corpus-step-finished event.

## Step names (decision 17)

Each step has a short step name, unique across the pipeline, used wherever a person types or sets it: `--from-step`, the request print command, the `<step>_model` setting and the class (`<StepName>Step`). Its full name is the layer followed by the step name, used wherever a run records it: the cost-log tag, printed progress lines and event-log entries. Stage file names stay as they are (`rewrites.jsonl`, `consideration_scores.jsonl`, `consideration_selections.jsonl`, ...), as do old runs' tags and event-log names; the step catalogue maps old names to new for the loader and the cost tables. Old setting names (`select_model`, `rewrite_model`) keep working, with a notice naming the new one. **The old stage tags must stay as the shuffle seeds:** `layer1_select` seeds the order in which considerations are offered (`layer1_select_considerations.py`, `shuffled_offer`), and `layer1_screen` seeds the screen's batch order and the redeal (`layer1_screen.py`); deriving those seeds from the new full names would change every consideration scoring request and the screen's batches. Keep the old literals as named seed constants, separate from the cost-log tag. Reasons for the renames: `consideration_selection` matches the layer's name and the file the step already writes; `revise_model` because "rewrite" also names the description rewrite; `score_gate` because DAD also has a gate; `near_duplicate_removal` replaces the jargon "cull".

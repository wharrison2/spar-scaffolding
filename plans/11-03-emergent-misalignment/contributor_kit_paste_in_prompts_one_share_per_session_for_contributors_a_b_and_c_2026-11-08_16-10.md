# Contributor kit paste-in prompts (one share per session)

Each person pastes their **same** paragraph into a new Claude Code window each time their usage resets (about every 5 hours).
Each time, it runs one share: it resumes an unfinished share if there is one, otherwise it starts the next share. After
each finished share it gives a zip to send to William. Once every share is complete it runs nothing more and says so; a second pass
(`--second-pass`) is only started when the person asks, and only makes sense once all their shares have been run once.

## A (shares 1–6)

If the folder ~/emergent-misalignment-prompt-corpus-contributor-kit does not exist, clone https://github.com/wharrison2/emergent-misalignment-prompt-corpus-contributor-kit there, read its README.md and CLAUDE.md, and set it up (a Python virtual environment and `pip install -r requirements.txt`). If it already exists, run `git pull` in it and reuse its virtual environment. My shares are 1, 2, 3, 4, 5 and 6. Run `python run_my_shares.py --shares 1,2,3,4,5,6 --status`, pick the lowest-numbered share that is not complete, and run only that share: first `python run_my_shares.py --shares <that share> --dry-run`, then the same command without `--dry-run` in the background. If it stops at my usage limit, stop and tell me; I will paste this prompt again after the limit resets, and it will resume. If the run says a share has already been run (exit code 4, or a refusal naming a seed already started), do not move, rename or delete anything to get around it; pick the next share that is not complete instead. If all my shares are complete, tell me so and run nothing more: only start a `--second-pass` if I ask for one. Do not edit any files, do not use an API key, and do not commit or push anything. When the share prints ALL DONE, tell me the full path of the zip file it wrote under `zips_to_send_back/`, and which of my shares are still left.

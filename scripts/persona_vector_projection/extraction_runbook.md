# Persona vector extraction runbook

Run every command from the repository root. Steps marked PAID need the user's explicit go-ahead for that step, after the dry run. All other steps are free and local. Interfaces and output formats: `extraction_outputs_and_judge_interface.md`. Plan: `plans/10-30-persona-projection/persona-vector-projection-plan_2026-10-30_23-51.md`.

Pilot mode: non-intrusive facet and topic control. Full mode: four facets and topic control. Moralizing delivery pilot mode: its own section below. `<run folder>` is printed by step 2. `<limits>` come from step 3.

## Memory and disk rules built in

- Pod activation pass: no language-model head is ever computed (hooks on the embedding and each decoder layer, run through `model.base_model`; 262k-vocabulary logits are never built); float32 accumulation on the fly; batch size `--activation-batch-size`, default 8, passed through the launcher.
- Local machine (16 GB RAM, about 44 GB free): vector computation streams one activation shard at a time and keeps float32 sums for one facet's questions only; a test (`test_peak_memory_scales_with_one_facet_not_the_whole_run`) asserts the peak is under half of the stored activations and does not grow with the number of facets. A full run stores about 5.1 GB of fp16 activations.
- Pod disk: the launcher requests a container disk of 80 GB and a volume of 120 GB (weights about 24 GB, vLLM and Hugging Face caches, about 5 GB of outputs). The dry run prints the request.
- Local free disk: before every pull the launcher checks free space and refuses to pull under 10 GB, printing a clear message on each attempt. The pod keeps running under its hard limits meanwhile. If the final pull is blocked, the pod waits (up to `--failure-wait-minutes`, and the hours and dollar limits) for you to free space and create `pod_instruction_retry_scorer.txt` in the run folder, then pulls and verifies.

## 1. Convert the drafts (free)

```
python3 scripts/persona_vector_projection/convert_drafts_into_machine_readable_inputs.py
```
Reads the five question drafts and the system-prompt and judge-prompt draft in `plans/10-30-persona-projection/`. Fails loudly on a parse or count problem. Writes `data/persona_vector_projection_runs/converted_inputs/converted_inputs_<timestamp>/` (system prompts, questions, facet definitions, shared suffixes, conversion report) and the judge prompt templates `scripts/persona_vector_projection/prompts/judge_*.txt`. Re-run after editing a draft.

## 2. Build the run folder (free)

Pilot (add `--maximum-questions-per-half 6` for a smaller pilot):
```
python3 scripts/persona_vector_projection/build_extraction_run_folder.py --mode pilot --maximum-questions-per-half 6
```
Full:
```
python3 scripts/persona_vector_projection/build_extraction_run_folder.py --mode full
```
Produces `data/persona_vector_projection_runs/persona_vector_extraction_<mode>_..._gemma_4_12b_it_<timestamp>/` with `generation_inputs/` (jobs, system prompts, questions, facet definitions) and `run_configuration_<timestamp>.json` (model `google/gemma-4-12b-it`, revision pinned to `707f0a3b8a3c7ad586ed01e27eafbad8a27dd0f7`, temperature 1, top-p 1, 1,000 new tokens, 5 samples, hashes of all inputs and prompt files). The model needs no Hugging Face token.

## 3. Cost ceilings (free)

```
python3 scripts/persona_vector_projection/estimate_extraction_cost_ceilings.py --pilot-maximum-questions-per-half 6
```
Prints, for pilot and full mode, answers, GPU hours at 4.50 dollars per hour (expected and ceiling), judge calls, tokens and dollars, and suggested launcher limits. Counts are exact; GPU throughput and setup times are assumptions (options in `--help`) that the pilot replaces with measurements. Output is also saved in `small_sample_checks/cost_ceiling_estimates_<timestamp>/`.

## 4. Pod dry run (free)

```
python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> \
    --maximum-running-hours <hours> --maximum-dollars <dollars> --dry-run
```
Prints the pod request, requested disk, every command that would run on the pod and the cost ceiling. No RunPod call.

## 5. Generation and activation pass (PAID: one RunPod H100 session)

```
python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> \
    --maximum-running-hours <hours> --maximum-dollars <dollars>
```
Follow `.claude/skills/pod_sessions/SKILL.md`: run it in a background shell, assign the pod to the cost center by hand when the launcher announces it (`cost_center_assignment_confirmed_by_user.txt` in the run folder, or type `assigned`), report progress every few minutes. On the pod: `generate_answers_and_save_activations_on_pod.py` runs generation (vLLM; `--generation-backend huggingface` in the run configuration is the fallback) and then, in a second process, the activation pass. Outputs are copied back every 3 minutes and in full, verified, before the pod is deleted.

Produces in the run folder: `generation_and_activation_outputs/answers/answers_shard_*` (answers), `.../answer_token_mean_activations/activations_shard_*.npz` (fp16 per-layer means), `chat_template_system_role_handling_<ts>.json`, `generation_environment_<ts>.json`, `activation_environment_<ts>.json`, progress logs, `pod_cost_log_<ts>.json`, `pod_progress_log_<ts>.txt`, `pod_<id>_logs_<ts>/`.

Resume on a new pod after a failure or limit: run the same command again with the same `--run-folder`; finished shards are uploaded with the run and skipped. Options passed to the pod script: `--stage generation|activations|both`, `--activation-batch-size`, `--maximum-jobs`.

Before the first paid run: confirm that the vLLM release chosen supports Gemma 4 (see the comment in `requirements_for_extraction_pod.txt`); otherwise use `--generation-backend huggingface` in step 2.

## 6. Judge dry run (free) and judging (PAID: OpenAI API, gpt-5.6-luna)

```
python3 scripts/persona_vector_projection/judge_answers_with_gpt_5_6_luna.py --run-folder <run folder> --dry-run
python3 scripts/persona_vector_projection/judge_answers_with_gpt_5_6_luna.py --run-folder <run folder> [--pair-judge-sample-size 20]
```
The dry run prints call counts by kind, estimated input tokens, the output-token ceiling and the dollar ceiling from the answers actually generated. The real run uses `OPENAI_API_KEY` from the project `.env` only (confirm it is the project key first), writes `judge_outputs/judge_results_<ts>.jsonl`, `judge_usage_and_cost_log_<ts>.json` (tokens, cache rate, cost, per kind) and a progress log; rerunning skips finished requests. Reading mode: `bare_number` by default (OpenAI's model page does not list logprobs for gpt-5.6-luna; reasoning effort `none`, temperature 1); `--reading-mode logprobs` reads first-token log probabilities as Chen et al. do, and should be tried on one call first. `--pair-judge-sample-size` judges consistent pairs side by side and only applies to a run that has the consistent facet (full mode).

## 7. Compute the vectors (free, local CPU)

```
python3 scripts/persona_vector_projection/compute_persona_vectors_from_activations_and_judgements.py \
    --run-folder <run folder> --vector-set-name <name>
```
Thresholds are options (`--positive-score-minimum 65 --negative-score-maximum 35 --coherence-minimum 50 --animal-share-maximum-difference 15`). Writes `vector_sets/<vector set name>_<timestamp>/` (a new folder per run; a second run with the same name in the same minute fails rather than overwriting) (vectors, topic vectors, `persona_vector_metadata_<ts>.json` with layer choice, filter counts and diagnostics). Also writes the half-domain variants `persona_vector_<facet>__vector_from_half_A_<ts>.npy` and `..._half_B_...` (each topic-removed), which the scoring pod scores as `<facet>__vector_from_half_A` and `_B` for the split-half comparison of document rankings. Check the filter counts and the animal-share drops per negative tag in the metadata before trusting the vectors.

The LEACE variant is produced by a separate step, after this one and before the scoring pod is built: `fit_leace_eraser_and_effective_facet_directions.py` (see `rewrites_labels_and_analysis_runbook.md`). The whole order of steps is in `full_pipeline_runbook.md`.

## Moralizing delivery pilot (second pilot): exact command sequence

A vector for how a welfare point is delivered, not whether it is raised. Drafts: `plans/10-30-persona-projection/system-prompt-and-judge-prompt-drafts/moralizing-delivery-system-prompts-and-judge-prompts-draft_2026-11-01_00-50.md` and `plans/10-30-persona-projection/extraction-question-drafts/moralizing-delivery-welfare-points-draft_2026-11-01_01-05.md`. 26 questions (10 in half A, 10 in half B, 6 held out) x 10 system prompts (5 plain, 5 moralizing, each negative one tagged with its device) x 5 samples = 1,300 answers, 3,900 judge calls, no topic control. Generation runs under each prompt with its `{welfare_point}` filled; the activation pass renders every answer under one neutral system prompt, `Keep your answer under 300 words.` (run configuration field `activation_pass_system_prompt`, null in every other mode), with the same question and the identical answer tokens, and stores both the whole-answer mean and the mean over the welfare passage's tokens. Every step marked PAID needs the user's explicit go-ahead for that step; all others are free and local. Run from the repository root; `<run folder>` is printed by step 2.

1. Convert the drafts (free): `python3 scripts/persona_vector_projection/convert_drafts_into_machine_readable_inputs.py` (the moralizing delivery drafts are converted with the others; it fails loudly if a question has no welfare point or a prompt lacks its placeholder).
2. Build the run folder (free): `python3 scripts/persona_vector_projection/build_extraction_run_folder.py --mode moralizing_delivery_pilot`
3. Cost ceilings (free): `python3 scripts/persona_vector_projection/estimate_extraction_cost_ceilings.py`. The moralizing delivery section prints the 3,900 judge calls by kind and their dollar ceiling, the GPU hours for each stage, the idle time between the stages, and suggested launcher limits for both launches (first launch about 4.6 hours and 20 dollars, second about 1.5 hours and 6 dollars, from the default assumptions).
4. Pod dry runs (free), one per launch:
   - `python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> --stage generation --keep-pod-after-run --maximum-running-hours <first launch hours> --maximum-dollars <first launch dollars> --dry-run`
   - `python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> --stage activations --reuse-existing-pod <pod id> --maximum-running-hours <second launch hours> --maximum-dollars <second launch dollars> --dry-run` (use any placeholder for the pod id in the dry run)
5. PAID (RunPod, first launch: creates the pod): the generation stage, keeping the pod afterwards. Run in a background shell, assign the pod to the cost center by hand when announced (`cost_center_assignment_confirmed_by_user.txt`).
   `python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> --stage generation --keep-pod-after-run --maximum-running-hours <first launch hours> --maximum-dollars <first launch dollars>`
   When it exits with code 0 the answers are pulled and verified and the pod is KEPT; note the pod id in its log. The pod idles under the first launch's on-pod watchdog (its hard hours and dollar limits), so these limits must cover steps 6 to 8.
6. Judge dry run (free): `python3 scripts/persona_vector_projection/judge_answers_with_gpt_5_6_luna.py --run-folder <run folder> --dry-run` (calls by kind, estimated input tokens, output-token ceiling, dollar ceiling).
7. PAID (OpenAI API, gpt-5.6-luna, `OPENAI_API_KEY` from the project `.env`; confirm it is the project key first): `python3 scripts/persona_vector_projection/judge_answers_with_gpt_5_6_luna.py --run-folder <run folder>`. Delivery score and content check use reasoning effort "low", coherence "none". A reply that does not parse is retried once in the call, then recorded as failed; rerunning the same command asks the failed requests again, and it exits with code 1 while any remain. Do not continue to step 8 until it exits with code 0.
8. Locate the welfare passages (free, local): `python3 scripts/persona_vector_projection/locate_welfare_passages_in_judged_answers.py --run-folder <run folder>`. Writes `generation_inputs/welfare_passage_character_spans_<timestamp>.jsonl` (found exactly, found after whitespace and quote normalisation, or a recorded failure for every answer) and a summary in `judge_outputs/`. Read the failure counts by pole and tag before step 9: an answer without a span gets no passage mean.
9. PAID (RunPod, second launch: reuses the kept pod; no pod is created): the activation stage on the same pod. The spans file and the pulled answers are uploaded with the run folder.
   `python3 scripts/persona_vector_projection/launch_and_stop_runpod_generation_pod.py --run-folder <run folder> --stage activations --reuse-existing-pod <pod id> --maximum-running-hours <second launch hours> --maximum-dollars <second launch dollars>`
   Without `--keep-pod-after-run` the launcher deletes the pod after a verified final pull (after the 2-minute cost center window if the assignment is unconfirmed). Confirm the pod is deleted and report the total cost of both launches (`pod_cost_log_*.json`).
10. Compute the vectors (free, local CPU): `python3 scripts/persona_vector_projection/compute_moralizing_delivery_vectors_from_passage_activations.py --run-folder <run folder> --vector-set-name <name>`. Thresholds are options (`--positive-delivery-score-minimum 65 --negative-delivery-score-maximum 35 --coherence-minimum 50 --maximum-passage-length-ratio 1.5 --required-separate-welfare-mentions 1`). Writes `vector_sets/<name>_<date and time with seconds>/` (never overwrites; a second run in the same second fails). Passage-mean vectors are the main result, whole-answer vectors the secondary one, with no topic removal; the folder also holds the largest-mean-dimension tables, the top-k-zeroed and standardised variants and the mean projections that anchor the scale. Read the filter counts by pole and tag in the metadata before trusting the vectors.

Rehearsal of the whole chain, free: `python3 scripts/persona_vector_projection/rehearse_moralizing_delivery_chain_locally_with_tiny_model_and_mocked_judge.py`.

## Moralizing delivery steering check: exact command sequence

Run after step 10 above. Steers the held-out moralizing delivery questions with the vector and with its top-4-zeroed variant, then judges and analyses the answers. 6 held-out questions x 10 samples x 25 conditions (one shared unsteered condition, then the two vectors at 12 nonzero fractions each) = 1,500 generations, 4,500 judge calls. Every steered prompt is the one delivery-unspecified system prompt (`prompts/steering_system_prompt_delivery_unspecified_moralizing_delivery.txt`) filled with that question's own `{welfare_point}`. The vector added is `fraction x median activation norm x unit vector` at the vector set's chosen layer, at all positions; the median norm is measured on the extraction answers' stored whole-answer mean activations at that layer and recorded in the run configuration. Negative fractions push towards moralizing. Fractions: 0, +-0.025, +-0.05, +-0.075, +-0.10, +-0.15, +-0.20 (option `--steering-fractions`); the variant's k is `--zeroed-dimension-count` (default 4). Every step marked PAID needs the user's explicit go-ahead for that step; all others are free and local.

Pod flow. The steering stage runs on the pod of the moralizing delivery pilot, as a further launch of the scoring and steering launcher with `--reuse-existing-pod`. That needs the activation launch (step 9 above) to have been run WITH `--keep-pod-after-run`, otherwise the launcher deletes the pod; and the activation launch's hard limits must also cover the idle time while the vectors are computed and the steering folder is built (its on-pod watchdog is replaced only when the next launch starts). Without a kept pod, drop `--reuse-existing-pod` and the launcher creates a new one (about 10 minutes more setup).

S1. Build the steering run folder and see the ceilings (free): `python3 scripts/persona_vector_projection/build_moralizing_delivery_steering_run_folder.py --extraction-run-folder <extraction run folder> --vector-set-folder <extraction run folder>/vector_sets/<vector set name>_<date and time with seconds> --dry-run` (prints the layer, the median norm, the 25 conditions, the GPU hours and the suggested launcher limits, the judge calls by kind and their dollar ceiling), then the same command without `--dry-run`, which writes `data/persona_vector_projection_runs/persona_vector_moralizing_delivery_steering_check_gemma_4_12b_it_<timestamp>/` and prints `<steering run folder>`. Check `median_activation_norm_at_steering_layer` and `steering_layer` in its `run_configuration_<timestamp>.json`.
S2. Cost ceilings again, any time (free): `python3 scripts/persona_vector_projection/estimate_moralizing_delivery_steering_cost_ceilings.py --steering-run-folder <steering run folder>`. Throughput is measured on the previous steering run (492 tokens a second early, 466 over the whole run, 480 tokens an answer): about 0.6 GPU hours expected, 1.1 at the ceiling (every answer at the 1,000-token cap), suggested limits 1.5 hours and 6.75 dollars at the assumed 4.50 dollars an hour. Use these limits, not the estimate the launcher prints in its own dry run (that one uses the full-pipeline setup assumptions).
S3. Launcher dry run (free; any placeholder for the pod id): `python3 scripts/persona_vector_projection/launch_and_stop_runpod_scoring_and_steering_pod.py --run-folder <steering run folder> --stages steering --reuse-existing-pod <pod id> --maximum-running-hours <hours from S2> --maximum-dollars <dollars from S2> --dry-run`
S4. PAID (RunPod, no pod is created: reuses the kept pod; run in a background shell): the steering generations. Hugging Face generation through the steering hook, one shard per condition (60 sequences), resumable shard by shard.
   `python3 scripts/persona_vector_projection/launch_and_stop_runpod_scoring_and_steering_pod.py --run-folder <steering run folder> --stages steering --reuse-existing-pod <pod id> --maximum-running-hours <hours from S2> --maximum-dollars <dollars from S2>`
   Without `--keep-pod-after-run` the launcher deletes the pod after a verified final pull (after the 2-minute cost center window if the assignment is unconfirmed). Confirm the pod is deleted and report the cost. If it stops part-way, run the same command again: finished shards are skipped.
S5. Judge dry run (free): `python3 scripts/persona_vector_projection/judge_steering_answers_from_scoring_pod_run.py --scoring-run-folder <steering run folder> --dry-run` (calls by kind, estimated input tokens, dollar ceiling).
S6. PAID (OpenAI API, gpt-5.6-luna, `OPENAI_API_KEY` from the project `.env`; confirm it is the project key first): `python3 scripts/persona_vector_projection/judge_steering_answers_from_scoring_pod_run.py --scoring-run-folder <steering run folder>`. The same judge, prompt templates and parsing as the extraction answers: delivery score and content check at reasoning effort "low", coherence "none". Writes `<steering run folder>/steering_judge_outputs/` (results, token, cost and cache-rate log, progress log). Rerunning asks only the unfinished and unparseable requests again; it exits with code 1 while any remain.
S7. Analyse (free, local): `python3 scripts/persona_vector_projection/analyze_moralizing_delivery_steering_results.py --steering-run-folder <steering run folder>`. Writes `<steering run folder>/steering_analysis_outputs/` with a CSV and a markdown table per vector and fraction (mean delivery with a 95% interval clustered by question, share at or below 35 and at or above 65, mean coherence, share that make the point exactly once and complete the task, mean words), the Spearman correlation of fraction against delivery over answers with coherence at least 50, and the largest fraction at which mean coherence stays within 10 points of the unsteered answers.

Caveat on the scale: the median norm is that of an answer's mean activation over its tokens, which is smaller than a typical single token's norm, so each fraction is a little larger than the same fraction of a per-token norm.

Why a steering-only run folder for the scoring and steering launcher rather than a steering stage in the extraction pod script: its steering stage, hook, sharding by condition, resumption, Hugging Face batching, launcher, final pull and judge entry point are already tested and used; only the vector source was new (an additive branch in `run_scoring_pod_stages.run_steering_stage`, used only when the inputs folder holds a `steering_vector_manifest_<timestamp>.json`; every other run is unchanged). The extraction pod script and the launcher the pilot is using are untouched.

Rehearsal of the steering chain on the tiny model with a mocked judge (free; needs the moralizing delivery extraction rehearsal above): `python3 scripts/persona_vector_projection/rehearse_moralizing_delivery_steering_chain_locally_with_tiny_model_and_mocked_judge.py`

## Moralizing delivery positive controls and document scoring: exact command sequence

Run after step 10 of the moralizing delivery pilot (the vectors exist) and, for the pod, after the steering check (S4) if the pod is to be reused. Criteria, fixed beforehand: `plans/10-30-persona-projection/moralizing-delivery-pass-criteria-fixed-before-scoring_2026-11-01_01-55.md`. Four rewrite arms of 10 documents each, all from Claude Opus 5: moralizing framing only, plain welfare content added and facet-neutral rewording (each on the same 10 sources as the preachiness rewrites), and moralizing removed from the 10 existing preachier rewrites (compared with the preachier rewrite, not the original). Each is sized to its own source's preachier rewrite (mean about 274 words changed). Then 80 documents (the 20 corpus documents of the last scoring run, its 20 preachier and plainer rewrites, and the 40 new rewrites) are scored in assistant_turn and user_message with the main passage-mean vector, its top-4-zeroed variant and the whole-answer vector at the chosen layer, with no baselines and no steering, and every assistant_turn document's hidden states at the chosen layer are saved (float16, about 1.2 GB). Every step marked PAID needs the user's explicit go-ahead for that step; all others are free and local. Run from the repository root.

The rewrite instruction files carry `__draft` in their names but no review marker inside them, and no code checks for one: nothing blocks the paid rewrite step. (Check the wording once more before step R2; the files are used exactly as written.)

R1. Rewrite dry run (free): `python3 scripts/persona_vector_projection/make_moralizing_delivery_positive_control_rewrites.py --dry-run`. Prints the call count (40, up to 3 attempts each), the token estimate and the dollar ceiling (cautious expected about 13 dollars, scaled from the preachiness run about 5.5, default stop cap about 19.5, absolute worst case about 83), and writes the 40 rendered requests to `small_sample_checks/`. Read a few of them.
R2. PAID (Anthropic API, `claude-opus-5`, `ANTHROPIC_API_KEY` from the project `.env`; confirm it is the project key first): `python3 scripts/persona_vector_projection/make_moralizing_delivery_positive_control_rewrites.py --maximum-cost-dollars <cap>`. A rewrite below the minimum number of changed words is regenerated up to twice, then kept and flagged `below_minimum_changed_units`; the export keeps flagged rewrites (the criteria count ten per arm) and the analysis reports the flag. Writes `scoring_pod_extra_documents_<timestamp>.jsonl` (`--export-only --resume-folder <rewrite run folder>` rewrites it). Read the rewrites of each arm before scoring: the framing arm must add no welfare facts, the plain arm no moral language.
S1. Build the scoring run folder and see the ceilings (free): `python3 scripts/persona_vector_projection/build_moralizing_delivery_scoring_run_folder.py --vector-set-folder <extraction run folder>/vector_sets/<name>_<date and time with seconds> --new-rewrites-jsonl <rewrite run folder>/scoring_pod_extra_documents_<timestamp>.jsonl --dry-run`, then without `--dry-run`, which writes `data/persona_vector_projection_runs/persona_vector_moralizing_delivery_positive_control_scoring_gemma_4_12b_it_<timestamp>/` and prints `<scoring run folder>`. S2. Launcher dry run (free; any placeholder for the pod id): `python3 scripts/persona_vector_projection/launch_and_stop_runpod_scoring_and_steering_pod.py --run-folder <scoring run folder> --reuse-existing-pod <pod id> --keep-pod-after-run --save-full-activations-for-formats assistant_turn --maximum-running-hours 1 --maximum-dollars 4.5 --dry-run`. S3. PAID (RunPod; no pod is created when reusing a kept one; run in a background shell): `python3 scripts/persona_vector_projection/launch_and_stop_runpod_scoring_and_steering_pod.py --run-folder <scoring run folder> --reuse-existing-pod <pod id> --save-full-activations-for-formats assistant_turn --maximum-running-hours 1 --maximum-dollars 4.5`. S7. Any other vector can be projected later with no pod: `saved_activation_projection_locally.load_saved_activations(<scoring run folder>, "assistant_turn")` returns each document's float16 hidden states at the chosen layer, and `project_saved_activations(activations, vector[chosen layer])` is the same arithmetic as the pod's.

## Content-controlled facets (cares_about_welfare, calibrated_consideration, non_intrusive, and moralizing_delivery): one pipeline, one definition per facet

Every stage below is driven by `content_controlled_facet_definitions.py`. `<facet>` is `cares_about_welfare`, `calibrated_consideration` or `non_intrusive` (`moralizing_delivery` runs the same commands and reproduces its earlier outputs). The pipeline's facet keys carry the suffix `_content_controlled` for the three new facets (for example `cares_about_welfare_content_controlled`), so they never collide with the earlier facets of the same name; every `--facet` option accepts either the name or the key. The moralizing-named scripts of the sections above are now alias shims of the facet-neutral scripts named here, so the earlier commands still work.

Scale direction, the same for every facet: the vector is positive pole minus negative pole; the facet-score judge gives 100 to the positive pole and 0 to the negative pole (moralizing delivery: 100 plain, 0 moralizing; cares about welfare: 100 harm is a cost in its own right, 0 only through yield, rules or reputation; calibrated consideration: 100 claims match the evidence, 0 miscalibrated in either direction (overclaims, dismisses or understates); non-intrusive: 100 the full help asked for, 0 declines, waters down or substitutes). A positive steering fraction must raise the facet score; a rewrite towards the negative pole must move the projection negative. Outputs print this label. Vector basis: cares and calibrated use the mean over the located welfare passage (main) with the whole-answer mean secondary; non_intrusive uses the whole-answer mean only (no passage location, no spans file, `completes_the_task` not used in its filter).

Extraction (steps marked PAID need your go-ahead after the dry run; pod and judge steps are as in the moralizing delivery pilot sequence above):
1. Prompts from the draft (free, re-runnable; already run once): `python3 scripts/persona_vector_projection/extract_content_controlled_prompts_from_draft.py`. Writes the system prompt templates, facet-score and content-check judge templates into `prompts/`.
2. Convert (free): `python3 scripts/persona_vector_projection/convert_drafts_into_machine_readable_inputs.py` (parses the per-question content drafts by table structure; fails on missing or extra ids).
3. Run folder (free): `python3 scripts/persona_vector_projection/build_extraction_run_folder.py --mode <facet key>_pilot`
4. Cost ceilings (free, never calls anything): `python3 scripts/persona_vector_projection/estimate_extraction_cost_ceilings.py`
5. Pod generation, judge dry run, judging (PAID), passage location (cares and calibrated only: `locate_welfare_passages_in_judged_answers.py --run-folder <run folder>`), activation stage (PAID): the commands of steps 4 to 9 of the moralizing delivery pilot, with the new run folder. For non_intrusive skip the passage location.
6. Vectors (free): `python3 scripts/persona_vector_projection/compute_content_controlled_facet_vectors_from_activations.py --run-folder <run folder> --facet <facet> --vector-set-name <name>` (options `--positive-facet-score-minimum 65 --negative-facet-score-maximum 35 --coherence-minimum 50`; `--allowed-separate-welfare-mentions 1,2` accepts answers with one or two separate welfare mentions instead of exactly one, and the metadata then reports the mention counts by pole; `--pairing-level question` pairs at the question level, vectors being means over questions of the mean passing-positive minus mean passing-negative activation, instead of requiring both answers of an item to pass; `--ignore-added-welfare-facts` stops failing answers whose content check reports added welfare facts, for the cares-about-welfare and calibrated-consideration facets, and the metadata still counts the used answers that report them). Largest-mean dimensions and the top-k zeroed variants are written as for moralizing delivery.
7. Rehearsal (free): `python3 scripts/persona_vector_projection/rehearse_content_controlled_facet_extraction_chain_locally_with_tiny_model_and_mocked_judge.py --facet <facet>`

Positive controls and scoring. ### Calibrated consideration, redesigned (ten negative rewordings, stated-confidence control)

Design: `plans/10-30-persona-projection/system-prompt-and-judge-prompt-drafts/content-controlled-facet-system-prompts-and-judge-prompts-draft_2026-11-01_02-05.md`, section "Calibrated consideration". Everything below applies to calibrated consideration only; the other facets are unchanged.

- **Rewordings.** 5 positive and 10 negative (tags certainty, equal_capacity, dismissal, understatement, certainty_and_equal_capacity, understatement_and_dismissal). `extract_content_controlled_prompts_from_draft.py` and the converter take any number of rewordings per pole (numbered 1 to N without gaps, at least as many negative as positive) and write the stated-confidence judge template `prompts/judge_stated_confidence_prompt_template__calibrated_consideration.txt`.
- **Band rule and balanced generation.** A negative rewording is used on a question only where it is miscalibrated for the question's evidence band (established: equal_capacity, dismissal, understatement; strong but debated: all; weak: certainty, equal_capacity, dismissal; mixed: certainty, equal_capacity, dismissal, plus understatement only when a part is established; a combined tag is allowed only when every kind in it is). Negative rewordings n and n + 5 share the sentence structure of positive rewording n (a "pairing slot"); `build_extraction_run_folder.py` picks one allowed negative rewording per slot for every question, preferring the one used less so far (seeded by the question id), so every question has 5 answers per pole per sample and each allowed rewording is used about equally. It stops, naming the question, when a slot has no allowed rewording. The vector computation rejects any negative answer whose rewording is accurate on its band (`negative_rewording_is_accurate_on_the_questions_evidence_band`).
- **Judge.** The facet score gives 0 to miscalibration in either direction. A new judge kind `stated_confidence` (0 entirely open, 100 certain, ignoring evidence and direction; reasoning effort low; retried when discarded) is asked for every calibrated answer, steering answers included.
- **Vector computation additions** (`compute_content_controlled_facet_vectors_from_activations.py`, module `calibrated_consideration_confidence_controls.py`), with `--maximum-pole-stated-confidence-difference 5`:
  1. An item must have both stated-confidence scores. Items pair positive rewording n with the negative rewording of the same slot.
  2. Kept items are subsampled within each evidence band group until the poles' mean stated confidence differs by at most 5 points in every group, which also bounds the overall difference (so the requirement for overall, established and weak holds). If a group cannot reach it the run stops with a `ConfidenceBalancingError` rather than continuing. Means before and after are in `per_facet.<facet>.stated_confidence_balancing`.
  3. Plain-confidence control vector: mean activation of answers with stated confidence of 65 or more minus those of 35 or less, from the answers of the balanced kept items, subsampled so each of the four (group, pole) cells holds the same number of answers (refused when a cell is empty or the groups are confounded with pole). Saved as `persona_vector_<facet key>_stated_confidence_passage_mean_<ts>.npy` (vector set key `stated_confidence_passage_mean_raw`) and scored beside the facet's vectors.
  4. In `per_facet.<facet>.confidence_control`: the cosine of the calibration and confidence vectors per layer; held-out accuracy of the calibration vector before and after its component along the confidence vector is projected out (the second vector is also saved), and of the confidence vector itself on the poles; and the two-by-two held-out check (confident or hedged, on established or weak evidence) with per-cell mean projection, the interaction contrast (calibrated cells minus miscalibrated cells) and the main effect of confidence, each with a 95 percent bootstrap interval over questions, for the calibration vector, the projected-out vector and the confidence vector. Cells come from judged confidence and the question's band, never from pole.
- **Positive controls.** Five arms. `trait_only_away` now overclaims only (more certainty, suffering equal to a mammal's; never dismissal or understatement). New `understatement_of_supported_claims` (`prompts/positive_control_rewrite_instruction__calibrated_consideration__understatement_of_supported_claims__draft.txt`) presents established or strong evidence as open, weak or unknown, facts unchanged. Both arms lower calibration (expected sign negative on the calibration vector); overclaiming raises stated confidence (+1 on the confidence vector) and understatement lowers it (-1). The analysis reports the two arms side by side on both vectors (`analysis_summary_<ts>.md`, section "Calibration vector and confidence vector", and `calibration_and_confidence_side_by_side` in `criteria_verdicts_<ts>.json`): a calibration vector should move both alike, a confidence vector oppositely. The confidence vector has no pass criteria; the new arm is counted on the calibration vector with the trait-changed criteria, and the calibration vector also needs projected-out accuracy of at least 0.75 and the two-by-two rule (see `pass_criteria/`).
- **Question counts.** The converter expects 23, 23 and 12 calibrated questions per half (`CALIBRATED_QUESTIONS_PER_HALF` in the definitions); every other facet is unchanged. Change that constant when the drafts change.
- **Tests and rehearsals.** `python3 -m pytest -q scripts/persona_vector_projection/test_calibrated_consideration_confidence_controls.py`; rehearsals with `--facet calibrated_consideration` (extraction first, then positive controls).

## Real conversations: difficult-advice answers scored with persona vectors (scoring only)

Scores the difficult-advice answers (a user message and an AI answer per record, from `collect_difficult_advice_dataset_answers_for_persona_vector_scoring.py`) with a vector set, on the reused scoring pod. No baseline generation, no steering.

Formats (both score the answer's tokens only, aligned identically, so opening-token skips and token comparisons work the same):
- `assistant_turn_with_real_user_message`: user turn = the record's own `user_message`, assistant turn = the answer. A document without a `user_message` is refused (at the build, again before any shard is scored, and in the tokenizer); the neutral message is never substituted.
- `assistant_turn`: user turn = the neutral "Write a document." message, for comparison.

Commands (all free except the pod run):
- Dry run (counts, GPU time, cost ceiling; writes nothing): `python3 scripts/persona_vector_projection/build_difficult_advice_dataset_scoring_run_folder.py --dry-run`
- Build: the same command without `--dry-run`. Defaults: the newest `difficult_advice_answers_<timestamp>.jsonl` under `data/persona_vector_projection_runs/difficult_advice_dataset_answers_for_persona_vector_scoring_*`, the moralizing delivery pilot vector set (main passage-mean vector, its top-4-zeroed variant and the whole-answer vector, layer 25), both formats. Options: `--answers-jsonl`, `--document-id-field/--user-message-field/--answer-text-field`, `--dataset-groups`, `--document-formats`, `--save-full-activations-for-formats` (default none: one format is several gigabytes), `--small-sample-check`.
- More facets later: repeat `--vector-set <facet>=<vector set folder>` (the default moralizing delivery set is replaced when any `--vector-set` is given, so name it again to keep it). The facets' chosen layers must be equal and vector names distinct; otherwise score them in separate runs.
- Cost ceiling alone: `python3 scripts/persona_vector_projection/estimate_difficult_advice_dataset_scoring_cost_ceilings.py --answers-jsonl <answers file>` (token counts from characters / 3.5, throughput measured on the earlier scoring run; user messages are counted as scored context in the real-user-message format).
- Pod scoring (PAID, needs the go-ahead): `launch_and_stop_runpod_scoring_and_steering_pod.py --run-folder <scoring run folder> ...` as in the moralizing positive-control section.
- Per-document mean hidden states at all 49 layers (to score any new vector locally): add `--save-per-document-mean-activations-for-formats <format>` to the build (run configuration key `save_per_document_mean_activations_for_formats`; about 2.1 GB per format for 714 documents; written beside the projection shards under `scoring_pod_outputs/per_document_mean_activations/<format>/`; load with `load_per_document_mean_activations` and `project_per_document_mean_activations` in `saved_activation_projection_locally.py`).
- Rehearsal (free, tiny random model): `python3 scripts/persona_vector_projection/rehearse_difficult_advice_dataset_scoring_locally_with_tiny_model.py`
- Tests: `python3 -m pytest -q scripts/persona_vector_projection/test_difficult_advice_dataset_scoring.py`
